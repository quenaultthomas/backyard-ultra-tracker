# Increment R.4 : Accueil, suppression de l'indicateur API et décor backyard

Quatrième incrément du jalon R (refonte graphique). Il retire de la page d'accueil (`/`) l'indicateur « API : disponible » et l'appel de santé qui l'alimente, retire le lien « Créer un compte » du corps de page (doublon du menu burger de R.2), et habille la page d'un **décor backyard** (courbes de niveau, boucle, sapins) avec un titre et une accroche, **identique pour le visiteur et pour l'utilisateur connecté**. **Aucun back, aucun contrat d'API, aucune règle métier, aucune route, aucune garde, aucune migration, aucune variable d'environnement, aucune dépendance npm, aucun changement de Caddyfile.**

## Ce qui est déjà livré (0.x à 3.6, R.1 à R.3), donc non respécifié

Vérifié dans le code :
- `Accueil` (`frontend/src/app/accueil/accueil.{ts,html,css}`, route `''`, titre d'onglet « Backyard Ultra Tracker ») : `<main class="accueil">` contenant le `h1.titre` (`data-testid="titre"`, « Backyard Ultra Tracker », `font-size: clamp(2rem, 6vw, 4rem)`), un `<p class="etat-api" role="status" aria-live="polite">` (puce + `<span data-testid="etat-api">` : « API : vérification… » / « API : disponible » / « API : indisponible »), et, si `session.etat() === 'ANONYME'`, un `<nav aria-label="Compte">` avec `lien-creer-compte` (« Créer un compte », `/creer-compte`). Le composant injecte `SanteApiService` et `SessionService`.
- `SanteApiService` (`frontend/src/app/sante/sante-api.service.ts`) et `reponse-sante.ts` : `GET /api/sante` au chargement puis toutes les 5 s (délai max 3 s). **Seul `Accueil` les utilise** (vérifié par recherche dans `frontend/src/`).
- `/api/sante` est un alias Caddy de `/actuator/health` (`frontend/Caddyfile`), documenté dans `docs/deploiement.md` (vérifications de déploiement avec `curl`). **Conservé tel quel** : il sert au déploiement, pas à l'écran.
- Charte R.1 (`docs/design.md`, `frontend/src/styles/*`) : 18 couleurs, motif de fond du `body` (courbes de niveau et boucle en `data:` URI, couleur `--couleur-trait`, **sans sapin : « réservés à la page d'accueil, R.4 »**), règle « pas de `svg`, `img`, `canvas` décoratif dans le DOM, motifs en CSS », CSP `img-src 'self' data:`. Budget Angular `anyComponentStyle` : avertissement à 4 kB, erreur à 8 kB (`frontend/angular.json`) : les tuiles du décor ne vont donc **pas** dans `accueil.css`.
- En-tête : titre + menu burger (R.2, R.3). Le pied de l'écran d'accueil n'a pas d'autre composant.
- E2E concernés (relevés par recherche) : `accueil.spec.ts` (CA14 et CA15), `creer-compte.spec.ts` (CA22), `connexion.spec.ts` (CA32, CA33), `menu-visiteur.spec.ts` (CA12), `theme-variables.spec.ts` (CA1, CA3), `theme-entete-motif.spec.ts` (CA8), `aide-theme.ts` (scène `accueil`).

Taille estimée (production hors tests) : ~120 lignes : `accueil.html` ~10, `accueil.ts` ~-20, `accueil.css` ~35, `styles/decor.css` ~25 (plus deux tuiles SVG en URI `data:` d'une ligne chacune), `styles.css` +1, suppression de `sante/` (~-60). Sous la cible (400) : pas de découpage.

**Décor**
- **RG4** : décor backyard, **100 % CSS**, sans élément de plus dans le DOM.

Au moins 5 silhouettes de sapin de 2 tailles au moins, en aplats `#1F5A43` (`--couleur-foret-survol`) et `#14352A` (`--couleur-foret`).

Plus visible que le motif du `body` (traits plus épais, boucle plus grande), mais de même couleur.

Toutes les couleurs des tuiles appartiennent aux 18 couleurs de la palette R.1 (les hexadécimaux en dur dans une URI `data:` sont l'exception documentée déjà admise pour le motif du `body`, qui ne peut pas utiliser `var()`). ## 3. Cas limites

- **Lisibilité** : texte posé sur un trait du décor (courbe ou boucle de couleur `--couleur-trait`) : ratios 8,62 (titre) et 9,67 (accroche), AA. Aucun sapin ne passe sous le texte : en paysage 640 x 360 ou à 200 % de texte, le contenu s'allonge, la page défile verticalement, le `padding-bottom` garde la bande de sapins sous l'accroche.
- **Mobile** : 320 x 640, 360 x 640 : titre sur 2 lignes (« Backyard Ultra » / « Tracker », selon la largeur), accroche sur 2 à 3 lignes, bande de sapins visible en bas, aucun défilement horizontal. Écran très haut (1080 x 1920) : le contenu reste centré, la bande est au bas de la fenêtre.
- **Écran très large** (1920, 2560) : la tuile de sapins se répète sans trou ni couture visible ; le titre atteint son maximum (4rem) ; l'accroche reste bornée à 32rem.
- **200 % de zoom du texte à 320 px** (`font-size` racine 32 px) : le titre vaut 64 px, un mot comme « Backyard » (~315 px) tend à dépasser 288 px de largeur utile : `overflow-wrap: anywhere` le coupe plutôt que de faire défiler la page (non-régression à vérifier, CA6). Reflow à 400 % de zoom navigateur = viewport de 320 px de large : couvert par CA5.
- **`prefers-reduced-motion: reduce`** : sans objet visible (aucune animation) mais vérifié : durées `0s`, `animation-name: none`.
- **Contraste forcé (`forced-colors: active`)** : le décor disparaît, le texte reste lisible dans les couleurs système. **`prefers-contrast: more`** : non traité (point ouvert 4).
- **API injoignable ou en erreur** (arrêt de `api`, coupure réseau, réponses 5xx) : la page s'affiche à l'identique, sans message ; l'en-tête garde son comportement existant (R.2 / R.3, `INCONNU` puis `ANONYME` ou menu). Le front n'émet plus aucune requête de santé, donc rien n'échoue silencieusement.
- **Session** : visiteur, coureur, bénévole, admin et admin master voient exactement la même page ; pendant `INCONNU` (jusqu'à 5 s) la page est déjà complète (l'en-tête seul est vide). Connexion ou déconnexion sur `/` : la page ne change pas (aucun rechargement visuel).
- **Utilisateur connecté qui ouvre `/connexion` ou `/creer-compte`** : redirigé vers `/` (garde existante, 1.2) : il voit le même accueil, sans lien « Créer un compte » (comme avant) ; ses entrées sont dans son menu.
- **Redimensionnement** : le décor suit (tuiles répétées, hauteur de bande en `rem`), pas de saut de mise en page ; menu burger ouvert sur l'accueil : le panneau recouvre le haut de la page (R.2), le décor ne gêne ni l'ouverture ni le focus.
- **Réseau lent** : le décor est inclus dans la feuille de styles (URI `data:`) ; aucun chargement d'image différé, aucun fond qui « saute ».
- **Chemin inconnu** (`/n-importe-quoi`) : redirigé vers `/` (route `**`), même accueil.
- **Non applicables** (aucune règle ni donnée métier ne change) : Boucle (au sens métier : le décor ne la représente que graphiquement), Passage, vainqueurs partagés, `CORRECTION` vs `SCAN`, plusieurs Courses, Course non démarrée, Inscription sans Passage, Réintégration, bénévole non affecté, rôle insuffisant (la page est publique, aucun accès n'est accordé ni retiré).

## 8. Points ouverts

Bloquants : aucun. Positions par défaut appliquées dans la spec.

1. **Texte de l'accroche.** Le roadmap parle d'« accroche » sans la rédiger. Position retenue : « Une boucle après l'autre, jusqu'au dernier debout. » (neutre : la durée d'une Boucle est un paramètre de la Course, donc rien sur « une heure »). À valider ou à remplacer par l'utilisateur.
2. **Retrait du lien `lien-creer-compte` du corps de page.** La ligne R.4 du roadmap ne le mentionne pas ; R.2 (point ouvert 4) renvoyait la décision ici et R.3 liste « doublon `lien-creer-compte` » en R.4. Position retenue : retrait, la création de compte reste accessible par le menu visiteur, `/creer-compte` et l'écran de connexion. Alternative : le conserver comme appel à l'action sous l'accroche (un bouton `.bouton` plutôt qu'un lien) ; à confirmer.
3. **Sapins en bande basse plutôt que dispersés.** Pour garantir la lisibilité (AA) sans fond de carte sous le texte, les sapins sont confinés à une bande de 6rem en bas. Alternative : sapins sur les côtés de l'écran large (plus de travail de mise en page, plus de risque à 320 px). À confirmer visuellement après la recette.
4. **`prefers-contrast: more` non traité** (seul `forced-colors` masque le décor). Le texte est de toute façon à plus de 8 de contraste sur le décor. Alternative : masquer aussi le décor en `prefers-contrast: more`.
5. **Alias Caddy `/api/sante` conservé** (utilisé par `docs/deploiement.md`) bien qu'aucun écran ne l'appelle plus. Un nettoyage éventuel (alias et documentation) relève d'une décision de déploiement, pas de cet incrément.
6. **Accueil en « hero » sans données** : l'accueil de 6.4 (liste des courses) viendra s'y ajouter ; le titre, l'accroche et le décor seront à revoir à ce moment. Rien n'est anticipé ici.
7. **Décor non animé.** Une boucle qui se dessine ou des sapins qui bougent serait possible, mais est renvoyé à R.9 (finition) avec la règle `prefers-reduced-motion`.
8. **Une tuile propre au décor plutôt que le motif du `body` agrandi.** Choix retenu pour que le décor se lise comme une illustration (traits plus épais, boucle plus grande) et pour recouvrir le motif du `body` (fond opaque). Coût : deux motifs de courbes cohérents mais distincts, documentés dans `docs/design.md`.
9. **Test CA15 remplacé et non supprimé.** La règle « un test n'est jamais supprimé » est respectée par le remplacement du test d'indicateur par son contraire (CA1 / CA8) ; le roadmap prévoit explicitement cette suppression de fonctionnalité.
10. **Taille.** ~120 lignes de production : pas de découpage.
