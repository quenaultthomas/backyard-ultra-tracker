## 3. Cas limites

- **Écrans en cartes** : liste vide (états vides de l'Espace coureur, de Mes inscriptions, de l'Espace bénévole, de Gestion des courses) ; une carte, nombreuses cartes ; nom de Course de 100 caractères sans espace dans chaque carte (coupé, jamais tronqué) ; Course sans logo (visuel de substitution) ; dossard à 3 chiffres ; Course complète ; coureur inscrit puis désinscrit (confirmation en ligne dans la carte) ; carte de Course avec confirmation de suppression ouverte à 360 px et à 200 %.
- **Messages** : un message de chaque type (erreur, succès, information) sur chaque écran qui en affiche ; erreur générale d'un 409 d'inscription ; succès de désinscription ; message d'information après déconnexion et après suppression de son compte (connexion) ; message de suppression d'une Course en succès et en information ; plusieurs messages simultanés (succès et erreur de la fiche) ; message long coupé dans la carte.
- **Plusieurs Courses en parallèle** : chaque carte n'affiche que ses données ; aucune dépendance entre cartes.
- **Rôles** : inchangés (garde et API non modifiées) ; un coureur n'accède pas à Gestion des courses, un bénévole non affecté voit son état vide, aucun rôle ne voit d'écran différent.
- **Largeurs** : 1280, 768, 640, 360, 320 px ; texte à 200 % ; paysage 640 x 360.
- **Contraste forcé, mouvement réduit** : RG7.
- **Non applicables** (aucune donnée métier ne change) : calcul de Boucle, Passage `SCAN` / `CORRECTION`, Abandon, Réintégration, vainqueurs partagés, nombre maximum de Boucles, instants de bascule, Course non démarrée, inscription sans Passage. `/api/test/horloge` inutile : les statuts se posent comme dans `theme-composants.spec.ts` (`placerStatutCourseEnBase`, `placerStatutInscriptionEnBase`).
